# RealChart Split 웨비나

'매출 상승, 이익 감소'의 원인을 차트 하나로 좁혀 가는 원인 분석 대시보드 예제입니다. RealChart Split으로 차트 하나를 네 칸으로 나누고, 전체 매출·주문 추이 → 상품 → 비용 항목 순서로 원인 후보를 좁힙니다. 모든 수치는 가상 데이터입니다.

**RealChart 1.5.2 이상이 필요합니다.** 상품 막대 선택에 쓰는 `selection` 옵션(`visible`·`style`·`focus`·`unselectedStyle`)은 1.5.2부터 제공합니다.

`lib/`에는 npm에 공개된 `realchart@1.5.2`(2026-11-05 공개)의 코어·Split·스타일이 들어 있습니다. [파일 출처와 교체 기준](./lib/README.md)을 참고하세요.

## 실행

```bash
npm install
npm run dev
```

표시된 localhost 주소를 엽니다. Node.js 20.19 이상 또는 22.12 이상이 필요합니다. 라이선스(`lib/realchart-lic.js`)는 **`localhost`** 에서만 동작합니다(2026-12-31까지).

이 예제는 `lib/`의 브라우저 번들을 `script` 태그로 읽습니다. Split 모듈은 읽는 시점에 등록됩니다. npm 패키지로 옮길 때는 다음처럼 가져옵니다.

```js
import * as RealChart from 'realchart';
import 'realchart/split';
import 'realchart/realchart-style.css';

RealChart.createChart(document, 'chart', config);
```

## 발표 단계별 예제

데모 목록에는 단계마다 시작 데모가 하나씩 있고, 마지막에 완성 데모가 있습니다. `/` 또는 `/?demo=1-split`에서 시작합니다. 각 섹션에서 Config와 표시 예를 먼저 설명한 뒤, 마지막에 데모를 진행합니다(14·19·25·30·35장). 첫 데모에서는 Config를 직접 입력해 반영 상태를 확인한 뒤 원인을 질문합니다. 이후 단계는 시작 데모 `main.js`에 MCP 요청을 보내고, 변경된 화면을 확인합니다. 각 단계의 시작 데모는 앞 단계를 마친 상태이고, 그 단계에서 설명할 설정은 들어 있지 않습니다. 폴더명은 그 단계에서 다루는 내용이고, 폴더 안은 그 단계를 시작하기 전 상태입니다. 지연이나 오류 때는 다음 단계의 시작 데모로 넘어갑니다.

1. `stages/1-split/`: 금액과 건수를 한 영역에 겹쳐 놓은 차트. 여기서 위아래 두 칸으로 나누고 시간축을 공유합니다
2. `stages/2-title-legend/`: 칸만 나눈 상태. 여기서 칸별 제목과 범례를 배치합니다
3. `stages/3-shared-xaxis/`: 칸별 제목·범례까지 넣은 상태. 여기서 공유 시간축에 크로스헤어, 가이드 영역(행사 기간), 가이드라인(매출 목표)을 넣습니다
4. `stages/4-product-profit/`: 여기서 오른쪽 열, 상품별 실매출 막대, 손익 워터폴을 추가합니다
5. `stages/5-selection/`: 여기서 상품 선택 강조와 손익 칸 변경을 연결합니다
6. `stages/final/`: 다섯 단계를 마친 완성본. 주문 건수 라벨과 40분·45분 새 집계 반영을 더했습니다

각 `main.js`는 실행할 설정을 직접 담고 있으며, 런타임 단계 분기 없이 독립적으로 실행합니다. 발표는 다섯 단계이고, 첫 단계만 요청이 두 번이라 라이브 MCP 요청은 여섯 번입니다. 발표 단계 번호와 폴더 번호가 같습니다. 발표 자료는 [2026-11-slides.pdf](./2026-11-slides.pdf)이며, 단계마다 데모 장에 요청문이 있습니다.

화면 공유에서는 왼쪽 VS Code와 오른쪽 데모 페이지를 나란히 배치하고, 데모 상단의 **목록 숨기기**를 누릅니다. `/?demo=1-split&view=present`로 열면 목록이 접힌 상태로 시작합니다. 목록을 접어도 ↑↓ 이동은 유지됩니다. 기준은 공유 화면 1920×1080, 데모 창 폭 약 960px입니다.

공통 데이터는 루트 `data.js`에서 읽습니다. 완성본은 `stages/final/`입니다.

## 코드 읽는 순서

1. **[stages/final/main.js](./stages/final/main.js)**: 상단의 `const config = { ... }`가 전체 차트 설정입니다. `split`, `xAxis`, `yAxis`, `series`를 직접 확인할 수 있습니다. 상품 선택 처리는 `general.onSelectionChanged`에, 다음 5분 반영 처리는 차트 생성 아래에 있습니다.
2. **[data.js](./data.js)**: 시간 추이 데이터, 요청문에서 참고하는 상품별 값, 다음 두 시점의 가상 응답입니다.
3. **[stages/final/index.html](./stages/final/index.html)**: 완성 차트 영역과 조작 버튼입니다. 루트 [index.html](./index.html)은 모든 데모로 이동하는 사이드바 목록입니다.
4. **[style.css](./style.css)**: 화면 스타일입니다.

JavaScript와 Vite만 사용합니다. 각 예제의 차트 설정은 해당 `main.js`에 직접 작성하고, 루트 목록에서 예제 HTML을 엽니다. Vite의 `publicDir: 'lib'`로 라이브러리를 제공하므로 파일 복사 플러그인도 필요하지 않습니다.

## 데이터 교체

시간 추이(매출·이익·주문·취소)는 `data.js`의 `data`에서 가져옵니다. 금액 단위는 만 원입니다. 상품 막대와 손익 워터폴 값은 각 `main.js`의 config에 숫자로 직접 적었습니다. 상품 막대 데이터마다 손익 값 `costs`(정상가 매출, 할인, 원가, 배송비)를 넣고, 선택하면 그 값으로 워터폴을 바꿉니다. `products`는 요청문에서 참고하는 상품별 값이고, `updates`는 완성본의 40분·45분 가상 응답입니다. 행사 기간 가이드 영역은 25분~35분 고정입니다. 축 범위와 단위는 실제 데이터에 맞춰 조정합니다.

45분 전체 이익은 25분 대비 800만 원 감소합니다. 텀블러 −1,100만, 머그컵 +200만, 드립백 +100만을 합한 결과입니다. 텀블러는 정상가 매출이 3,600만 늘었지만 할인 1,200만·원가 2,600만·배송비 900만이 추가되어 이익이 1,100만 줄었습니다. 워터폴은 선택 상품의 **현재 누적 손익**을 표시합니다.

## 조작

- 상품 막대를 눌러 손익 상세를 바꿉니다. 왼쪽 전체 추이는 유지합니다. 처음에는 선택 없이 첫 상품(텀블러)의 손익이 보이고, 선택을 풀면 손익은 마지막 상품 그대로 남습니다.
- 다음 5분 반영으로 40분·45분 집계를 확인합니다. `addPoint`로 시간 추이에 점을 더하고, 상품 막대와 손익(첫 상품)을 새 값으로 바꿉니다. 상품 막대를 새로 넣으면 선택이 풀립니다. 두 번 반영하면 버튼이 비활성화되며, 처음 상태는 새로고침으로 돌아갑니다.

```bash
npm run build
npm run preview
```

## 구현 확인 순서

- **위치가 다르면** 축의 `row`·`col`과 시리즈가 연결한 축 이름을 확인합니다.
- **새 값이 안 보이면** 축 범위(`strictMax`)와 데이터의 단위를 확인합니다.
- **선택해도 손익이 안 바뀌면** 상품 시리즈에 `selection`이 켜져 있는지, 막대 데이터에 `costs`가 있는지 확인합니다.
- **상세가 맞지 않으면** 상품 식별자와 집계 시점을 확인합니다. 이 예제는 이름을 식별자로 쓰지만 서비스에서는 고유 ID가 적합할 수 있습니다.
